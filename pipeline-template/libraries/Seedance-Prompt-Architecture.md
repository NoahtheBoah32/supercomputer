# Seedance Prompt Architecture

The block-level architecture behind Higgsfield's Seedance work, reduced to rules we can
apply. Compiled Sep 2026 from Higgsfield's **own production prompt-writing skill**
(`seedance-clean`, shipped as a downloadable `.skill` on the Seedance-4K breakdown post),
the Seedance 2.5 prompting guide with its ten tested prompt categories, the Seedance-4K
full asset+prompt breakdown, and the *Cully Hill Boys* feature release.

> Scope note: prompt text and architecture only. Nothing here was generated by a model.
> This file is the **structural** companion to [Higgsfield-Prompt-Formats.md](Higgsfield-Prompt-Formats.md),
> which catalogues tokens, presets and verbatim example dumps. Where the two disagree,
> this file wins for Seedance — it is sourced from the vendor's own working skill rather
> than from blog surface.

confidence — this is what they actually run) · **[OFFICIAL]** = Higgsfield blog/docs ·

## 0. What *Cully Hill Boys* actually establishes  [OBSERVED + OFFICIAL]

The reference point for scale. Facts, not inference:

| Fact | Value |
|---|---|
| Runtime | **1 h 54 m 49 s** (6 889 s), measured off the HLS manifest — marketed as "110-minute" |
| Delivery format | **3438 × 1440**, master 4096 × 1716 → **2.39 : 1 scope** |
| Type | `film`, single continuous asset — not a shot showcase |
| Budget | **$2 M, ~half spent on tokens** — i.e. ~$1 M of rerolls to land 110 usable minutes |
| Schedule | ~4 weeks, script to finish |
| Script | Human screenwriter, hired. The story layer was not generated |
| Stack | Claude wrote the prompts · **Seedance 2.5** for video + speech · Seedream + Nano Banana for image/video edit |
| Cast | Licensed likenesses of real people (N3on, Israel Adesanya, Rampage Jackson, MKIATPIS) |
| Licence | `HOL-RO` (Higgsfield Originals, rights-owned) |
| Prompts | Published to the project **canvas**, gated behind a signed-in account — `showPrompts: true`, `showCanvas: true`, but the canvas payload is not served to an anonymous fetch |

**The two numbers that matter to us:** the reroll ratio (half the budget was failed
generations) and the fact that the screenplay stayed human. Both argue for spending
effort at [Ideation-and-Script-Library.md](Ideation-and-Script-Library.md) Stage 0 and on
locks, because that is where reroll cost is actually decided.

Two techniques leaked in the release thread and are worth keeping:

- **Dialogue gets a word count as its own lock.** A take whose only line is
  `"Pull it, Oli."` states *exactly three words* as a lock — otherwise the model fills
  the silence with a mumble or a line in another language. **Seedance does not like
  silence; it must be told the speech is finished.**
- **Music never comes from the model.** The track is recorded first, cut into
  **12-second blocks on the vocal's breaths**, and each block is fed in as an audio file.

## 1. Core principle — write the visible  [SKILL]

> The model reacts to what can be **seen and measured**, not to mood words.

Every abstraction gets translated into something observable:

| Don't | Do |
|---|---|
| "tense scene" | "man freezes, slowly clenches his fist, light only from the side, half his face in shadow" |
| "cool cinematic shot of a car, epic, fast" | "low tracking shot alongside the car as it powers through a wet curve, headlights glowing, spray off the tyres, hard buffeting camera shake" |
| "she looks sad" | "her eyes drop to the table, jaw tightens, she swallows once before answering" |
| "he is angry" | "knuckles whiten on the glass, breath shortens, eyes never leave hers" |

Plain instruction-style language. **Fewer precise words beat many vague ones.** Before
shipping, "watch" the prompt as a viewer: is the first frame non-empty, is it clear where
the subject is and where it looks, is it clear where the light comes from.

## 2. The block order  [SKILL]

Seventeen possible blocks, this order, **use only the ones the shot needs and drop the
rest**. The logic: context and references first, then space and timing, then action and
physics, then descriptive style in its home block, then a technical-style suffix, locks last.

```
SCENE CONTEXT        1–2 sentences: what happens, where, when. Geo-positions of characters.
ACTIVE REFERENCES    @tag + minimal anchor of critical details + "100% matches the reference"
LOCATION MAP         Foreground / midground / background, camera position, light origin, movement paths
FIRST FRAME / BLOCKING   Who is where in frame 1: position, orientation, gaze. Composition rule for THIS scene
FORMAT MODE          Which control level (§4)
OPTICS               Shot size + FOV° per segment + lens character. Multishot: add "no drift mid-segment"
CAMERA               Operator behaviour: height, distance, movement, focus. Body tonal character as a look
ACTION               Events at the precision the shot needs. Camera motion and subject motion stated SEPARATELY
PERFORMANCE          (when acting matters) muscle-level emotion, eye-line, catch-lights, breath, pore detail
PHYSICS              Mass, inertia, contact shadows, fluids, particles
LIGHTING             Source, direction, exposure — priority block
COLOR GRADE          (only when the grade is strong/stylised; otherwise fold into LOCATION + LIGHTING)
WARDROBE             (only when costume matters) material + condition, scene-logical
AUDIO                Only the needed sound / line
STYLE                Technical suffix: overall look in words, photoreal, format, grain
OUTPUT SETTINGS      (when format must be pinned) resolution, anamorphic, real-time vs slow-mo per segment
POSITIVE LOCKS       Short hard fixers against likely failures, in positive form. Continuity lives here
```

**CAMERA sits in 3rd position of the core layers** (subject → action → camera → style →
constraints). Moved to the end, FOV gets ignored; moved to the front, it fights identity.

A **lock** is a short hard fixer placed next to what it protects —
`"headlights stay glowing in every shot"`. Write densely where control matters, sparsely
where it does not. Say each important thing **once**, clearly.

### 2.1 Style is distributed, not a prefix  ⚠️ supersedes our older practice

There is **no style-prefix block at the top.** Style is a set of aspects, and each aspect
lives in the block that already governs it. The prompt opens on `SCENE CONTEXT`.

| Aspect | Home block |
|---|---|
| Lighting — source, direction, exposure, key/fill, haze | `LIGHTING` |
| Colour / grade | `COLOR GRADE` if strong, else folded into `LOCATION` + `LIGHTING` |
| Lens / optical character — FOV°, rectilinear vs anamorphic, motion blur | `OPTICS` |
| Camera body / tonal character — latitude, highlight roll-off, colour science | `CAMERA` |
| Skin / micro-realism — pores, capillary flush, living eyes, catch-lights | `PERFORMANCE` (or `ACTION`) |
| Acting — micro-pauses, eye-line, restraint | `PERFORMANCE` (or `ACTION`) |
| Physics realism — gravity, inertia, mass, contact shadows | `PHYSICS` |
| Composition / blocking | `FIRST FRAME / BLOCKING` |
| Continuity | `POSITIVE LOCKS` |
| Wardrobe — material + condition | `WARDROBE` |
| Format, resolution, grain, fps | `STYLE` + `OUTPUT SETTINGS`, **at the end**, just before locks |

Descriptive style sits *inside the content block it describes*. Technical/format style
forms a short **suffix stack** before `POSITIVE LOCKS`. Nothing style-related opens the prompt.

> **This contradicts §2.4 of [Higgsfield-Prompt-Formats.md](Higgsfield-Prompt-Formats.md)**
> — the labelled `Format: / Lighting: / Camera: / Skin: …` style header prepended to every
> shot. That header is real and officially published (the `cinematic_headphones` ad dump),
> but it is the **older** pattern. Higgsfield's own current skill explicitly rejects it.
> Treat the style header as legacy: fine for a quick ad where every shot shares one look,
> wrong for anything where light and lens change shot to shot. State the target look,
> never what to avoid, and adapt every line to the specific scene rather than pasting a block.

A naturalistic single take may carry no `COLOR GRADE`, `WARDROBE` or `OUTPUT SETTINGS` at
all. A graded multi-segment piece earns the full suffix stack.

If the user supplies their own prefix or block text, **use it verbatim.**

## 3. Asset tagging and context isolation  [SKILL]

The reference image (`@tag`) sets **appearance and identity**. Text sets **what happens**
and locks critical details. Both are required.

```
@TAG: age + role/build + current state + unique visible features + action-critical details
      + voice (only if it has a line). 100% matches the reference.
```

- **Keep the character description minimal.** Long appearance text *conflicts with the
  image and degrades it.* This is the opposite of how we write a still-image portrait prompt.
- **State critical details in words even when they are on the reference** — small text,
  logos, colour. The model drops them otherwise.
- **Never place an `@tag` in a shot where that object is not present.** The model will
  force it into frame.
- Tag naming: use the user's `@tag_name` if given; otherwise name by load order —
  `@image1 @image2 …`, `@video1 …`, `@audio1 …`.

### Context isolation

Each generation is a **blank slate with no memory of previous shots.** A prompt is a
sealed single-shot document. Never carry in: scene numbers, script headings, summaries of
prior scenes, unused tags or characters, "as above / continues" phrasing, or people and
props from a previous beat that this shot does not need.

> This is why our `@handle` asset registry
> ([Ideation-and-Script-Library.md](Ideation-and-Script-Library.md) Step 9) has to resolve
> to a *flattened* per-shot tag set at prompt time, not a scene-level one.

## 4. Cuts and timing — a scale, not a binary  [SKILL]

| Mode | Phrasing | Use when |
|---|---|---|
| **Single shot (oner)** | "one continuous shot, the camera does not cut on its own." | One unbroken move |
| **Sequential cuts** | `CUT 1 … CUT 2 … CUT 3`, described in order | Specific cuts, timing does not matter |
| **Timed multishot** | explicit `HARD CUT` at stated seconds | Beats must land on a clock |
| **Freestyle b-roll** | do not lock cuts | Let the model find angles |

Whenever cuts are specified, add the anti-auto-cut lock:
`"cuts only at the specified points, the camera does not cut on its own."`

```
Timecoded            Sequential
0.0s to 1.0s — …     CUT 1 — …
1.0s HARD CUT        CUT 2 — …
1.0s to 3.0s — …
```

Cut types: `HARD CUT` · `SMASH CUT` · `MATCH CUT` · `INSERT CUT` · `REVERSE CUT` ·
`WHIP CUT`. Fades and crossfades only on explicit request.

**Across internal cuts hold:** same character set, same geometry, screen direction, gaze,
light, wardrobe, prop state.

## 5. Optics — shot size and FOV  [SKILL]

Two levers define how it is shot: **shot size** and **focal length**. Write **FOV in
degrees** in the prompt, never millimetres.

| Abbr | Meaning | In frame |
|---|---|---|
| ECU | Extreme close-up | a detail: eyes, button, headlight, hand |
| CU | Close-up | full face / one element large |
| MCU | Medium close-up | head and shoulders |
| MS | Medium shot | roughly to the waist |
| WS | Wide shot | full figure + surroundings |
| EWS | Extreme wide | scale, location |

### FOV anchor table — use only these discrete steps

| FOV | mm equiv | Purpose | When |
|---|---|---|---|
| 180° | fisheye | spherical distortion | POV, dream-state |
| 107° | 14–16 mm | architectural ultra-wide | huge interiors, epic establish |
| 84° | 20–24 mm | wide | establish, group blocking |
| 63° | 28–35 mm | observational | wide observation, reportage |
| 47° | 40–50 mm | neutral human perspective | universal establish, medium |
| 29° | 75–85 mm | portrait compression | medium-isolate, dialogue bust |
| 18° | 100–135 mm | natural portrait | close portrait, identity-preserving |
| 12° | 180–200 mm | tele detail | hands, objects, detail-on-wide |
| 8° | 300–400 mm | extreme compression | observation, broadcast |

Not "23°" — round to 18° or 29°. In a multishot, **set FOV per segment and add
`"no drift mid-segment"`.**

Millimetre thinking is still how we *choose* (24–35 wide for action and immersion,
50 normal for realism, 85 for portrait separation, 135+ for compression and observation) —
it just never reaches the prompt text. Our
[Lenses/Zeiss-Supreme-Prime-Lens-Library.md](Lenses/Zeiss-Supreme-Prime-Lens-Library.md)
remains the selection tool; this table is the translation layer on the way out.

## 6. Optical techniques  [SKILL]

**Observation pattern (hidden-camera effect)** — all three ingredients at once, or it reads as a normal shot:
1. Foreground occlusion — out-of-focus obstruction over **20–30 % of frame** (wall, pillar, branch, arch).
2. Atmospheric haze between camera and subject.
3. Distance vantage — super-tele **8°–12°**, operator anchored far away.

Change the occlusion type between beats; keep the vantage single.

| Effect | Recipe |
|---|---|
| Sports broadcast | `8° super-tele` + handheld **1–2 cm tremor** + "anchored at distance, finding the action" |
| Detail-on-wide (snake cam) | `84°` + low angle right up against a small object — foreground exaggerated, background recedes |
| Intimate wide | `63–84°` on a close face — face centred, surroundings readable without blur |
| Tele compressed air column | at `8°–12°`: "dust suspended in the long compressed air column between camera and subject", "heat shimmer compressed into a wall of haze in front of the figure" |

## 7. Special protocols  [SKILL]

**4-mechanism multishot consistency stack** — mandatory at extreme FOV (8°, 107°).
All four, or extreme-FOV multishots break down after 2–3 beats:
1. Sequence-wide identity lock — a single location reference across all beats.
2. **LENS LOCK opener** — explicit FOV phrase at the start of each beat.
3. **LENS CHECK closer** — confirm FOV at the end of the beat.
4. Colour via material + light, never as a list.

**Whip-pan timing** — a whip under 0.8 s renders as a hard cut with no blur:
```
0.3s — Subject A settled
0.8s — WHIP motion-blur transition
1.4s — Subject B settled
```

**Mixed time-speed** — hard cuts only between speed modes. Each shot is one speed start to finish.

**Anti-impact lock** (cracks and breaks with no strike):
- "crowd PRESSES, not strikes"
- "fracture originates from edge stress, not center impact"
- "no impact point — pressure-based crack"
- sequential timing **edge-to-centre**, not radial from a point.

## 8. Prompting rules  [SKILL]

- **Positive only.** State the target, never the prohibition.
  ❌ "does not fall backward" → ✅ "stays upright, feet planted."
- **Speeds in km/h.** ❌ "fast" → ✅ "moves at 40 km/h", "camera pans at 5 km/h."
- **Atmosphere in percent / metres.** ❌ "light fog" → ✅ "fog density 40 %",
  "haze visible at 15 metres depth."
- **Atmosphere builds in steps across shots.** Shot 1 fog 20 % → Shot 2 40 % → Shot 3 60 %.
- **Giant scale by human-height comparison.** ❌ "huge", "three metres tall" →
  ✅ "stands as tall as four humans stacked head to toe."
- **Left/right is always from the camera.**
- **Environment interaction stated physically.** Snow melts on skin, rain runs down hair,
  wind moves fabric.
- **Emotion through muscle movement, not labels.**
- **White balance in Kelvin**, set to scene mood, fixed within a scene —
  3200 K / 4000 K / 5600 K / 8500 K.
- **Colour = material + light beam + compositional role, never a flat list.**
  ❌ "the woman wears red, the man wears blue" →
  ✅ "crimson silk scarf catching the cold tungsten spill from the corridor."
- **Background in layers** — foreground / midground / background stated separately.
- **Camera on the shadow side**, with a stated operator axis.
- **English only.**

### ⚠️ The equipment- and director-name rule — and where it breaks

The skill is categorical: **"No director names, no signature-work references, no
equipment names"** — describe the *look*, not the gear, because model names "get ignored
or break complex moves."

Higgsfield's own published Seedance 2.5 example prompts **violate this repeatedly** —
the action-sequence prompt names *Tenet*, *Sicario*, Michael Bay, Hoyte van Hoytema,
Greig Fraser, Roger Deakins, Wally Pfister, and specifies "Arri Alexa Mini LF plus Master
Anamorphic", "Arri Alexa 65", "Laowa 24mm Probe Lens". Those prompts are presented as
tested and working.

**Our reading:** the ban is a *robustness* rule, not a hard parser constraint. Names are
lossy shorthand that competes with the precise instruction next to it. So:
- Use [Film-Director-Library.md](Film-Director-Library.md) and the lens libraries to
  **decide** the look, then **render the decision as observable description.**
- If a name earns its place, pair it with the mechanism — Higgsfield's own working
  example hedges exactly this way: *"References in spirit, fully original execution."*
- Never let a name be the *only* carrier of an instruction.

This keeps our director/lens libraries load-bearing without betting a generation on a name.

## 9. Seedance 2.5 — the capability deltas  [OFFICIAL]

| Spec | Detail |
|---|---|
| Native resolution | up to 1080p |
| Max clip length | **up to 30 s** |
| Aspect ratio | any ratio from **9:16 to 21:9** |
| References | **up to 50 multimodal** in one generation — 30 images, 10 video, 10 audio |
| Audio | ambience, foley and score generated **in the same pass** as video |
| Consistency | holds identity, wardrobe and lighting across shots from a single reference |
| Region edit | fixes one spot without re-rendering the whole clip |

### What their multi-generation testing showed

- **Reference images hold identity across cuts far better than text description does.**
  Once a face or product is locked as a reference it survives hard cuts, lighting changes
  and camera moves that would otherwise drift.
- **Genre and lighting settings do more work than most of the prompt text.** Changing
  genre alone shifts pacing, contrast and camera behaviour with the scene text unchanged.
- **Multi-character scenes are the hardest category.** The more faces in one shot, the
  more reference material each needs to avoid collapsing into a generic face by the
  third or fourth cut.
- **Shot-by-shot beats a single continuous description** for anything with more than one
  camera angle. **Vague transitions are the most common cause of a sequence falling apart.**
- **50 references is a ceiling to use deliberately, not to max out.** A cluttered set with
  competing faces, props and locations is *less* coherent than a small chosen set.
  One reference per element that must stay consistent.
- **GLOBAL STYLE and AUDIO function as guardrails more than instructions.** Explicitly
  excluding what shouldn't appear prevents more failures than adding positive description.

> Note the last point sits in tension with §8's positive-only rule. Reconciliation: keep
> *instructions* positive, and keep **exclusions confined to the top style line and the
> audio line** — which is exactly the shape their example prompts take
> (`No music, no narration, no subtitles` / `no logos, no readable text`).

### Asset-building rules that feed the video stage  [OFFICIAL]

- **Character sheets on grey.** After extensive testing, grey outperforms white or black.
- **Two images minimum per character:** one with the face clearly visible, one full-body
  for the outfit — so the model never has to guess.
- **Locations at a 3/4 angle.** Shows more of the room, gives better depth perception,
  renders without breaking.
- **The input image decides the video.** "The better the input image, the sharper the
  final video." Examine every detail; regenerate if anything is off.
- Build every character, location and prop as a saved element **first**; the prompt then
  references them by tag.

> Our own [character-sheet default](.claude/skills/realist-portrait/SKILL.md) — a
> single-generation tiled grid with full-body front **and** back — already satisfies the
> two-image rule in one generation, and the grey-background finding is consistent with it.

## 10. Pre-flight checklist  [SKILL]

- Blocks in order — context/references, space/timing, action/physics, style in home blocks, technical suffix last?
- Tags named per rule; `@tag` only in shots where the object is actually present?
- No style prefix at the top — opens on `SCENE CONTEXT` / `ACTIVE REFERENCES`?
- Each style aspect in its home block?
- Style adapted to this scene, not generic?
- Everything positive, exclusions confined to the style and audio lines?
- Speeds in km/h, atmosphere in % / metres, giants vs human height?
- Emotion through muscle movement, not labels?
- Left/right from the camera?
- FOV from the anchor table in degrees — not mm, not arbitrary?
- CAMERA block in 3rd position?
- WB in Kelvin?
- Colour via material + light + role, not a list?
- Camera on the shadow side, operator axis stated?
- Background in foreground/midground/background layers?
- Multishot: FOV per segment + "no drift mid-segment"; extreme FOV → all four consistency mechanisms?
- Dialogue: word count stated as a lock, so the model knows the speech is finished?

## 11. What changes in our pipeline

| Our stage | Change |
|---|---|
| Stage 0 — ideation | Reroll economics justify the effort. Keep the script human-authored; that is what the $2 M film did. Flatten the `@handle` registry to a **per-shot** tag set (context isolation, §3). |
| Stage 1 — ground rules | Aspect ratio gains real range on 2.5: **9:16 → 21:9**. Scope reference point: 2.39:1. Clip ceiling **30 s**. |
| Stage 2 — stills | Character sheets on **grey**; locations at **3/4 angle**; the still decides the video. |
| Stage 4 — signature card | The `[style/mood]` slot should now **distribute** into home blocks rather than print as a header (§2.1). |
| Stage 5+ — shot prompt | Adopt the 17-block order, the FOV anchor table, `"no drift mid-segment"`, and the timing scale. |
| Negative prompts | Confine exclusions to the style line and the audio line; everything else positive. |
| Budget | Our ≤1500-char Seedance/Dreamina budget is a **Dreamina** constraint. Higgsfield's own working Seedance prompts run 2 000+ words. Note the conflict when writing for Seedance directly rather than for the shared budget. |
