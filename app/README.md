# SupaComputa

A local, Supercomputer-style chat app for the Leo Workflow pipeline. It runs on your own Claude Code login (Claude Agent SDK), keeps every file on this machine, and never exposes an API key to the browser.

## Opening it

- **Desktop icon `Supacomputah`** opens the app in its own window (Chrome app mode, no address bar). Also in the Start Menu.
- **Address:** `http://supacomputah/` in any browser (type it with the trailing slash so Chrome does not search for it). `http://supacomputa/`, `http://supacomputah.localhost/` and `http://127.0.0.1:8797` work too.
- **Always on:** `bin/service.vbs` in the Startup folder starts the server hidden at login and `bin/run-forever.cmd` restarts it if it ever exits. Log: `%LOCALAPPDATA%\SupaComputa\service.log`. You never need `start.cmd`.
- The friendly name is one line in `C:\Windows\System32\drivers\etc\hosts` (`127.0.0.1 supacomputah` and `127.0.0.1 supacomputa`); the server also listens on port 80 for it.

## Run it

1. Install Node.js 20 or newer and Claude Code (`npm install -g @anthropic-ai/claude-code`).
2. Double-click `start.cmd` (or run `npm install` then `npm start`).
3. The app opens at http://127.0.0.1:8797.

Screen 1 checks your Claude login and opens a terminal for `claude auth login` if needed. Screen 2 asks for your generation keys: ElevenLabs, Higgsfield (pasted as `KEY_ID:KEY_SECRET`) and fal. Fill in the ones you have, or skip. Each key is verified with a free read-only call (ElevenLabs subscription, Higgsfield price estimate, fal pricing) and stored in `%USERPROFILE%\.supacomputa\config.json` with owner-only permissions. Keys reach the pipeline only as environment variables (`ELEVENLABS_API_KEY`, `HIGGSFIELD_API_KEY`, `FAL_KEY`) and are never sent to the page again.

## Providers

- **Key priority** (Settings) is the provider new chats render with. The provider trigger in the composer (next to Ask / Auto) switches the current chat; a chat keeps its choice. If the chosen provider has no key, the first provider with a key is used.
- The pipeline's `tools/gen_image.py` reads `GEN_PROVIDER` and renders through ElevenLabs (GPT Image 2), Higgsfield (Soul 2, references uploaded to Higgsfield first) or fal (GPT Image 1.5, references as data URIs). Exit codes and the job `log.csv` stay the same; the model column names the provider's model.
- **Paths and prompts in chat.** A path never shows as `C:\Users\...`: it becomes a short blue link named after the item (character-01 v2, scene-01 still prompt, brief, a job folder). Media opens in the lightbox, a prompt or note file opens in the Inspect panel, anything else opens with its own app, a folder opens in Explorer. A prompt the agent shows you sits in a code box with **Copy** and a lime **Inspect** button; Inspect opens the approval-style panel with the text editable. Save writes the prompt file and tells the agent to read it again. The approval panel's prompt is editable too: click it, change it, Approve, and the render uses your words. The grip above either panel drags it taller (double-click snaps to the full prompt).
- **Chat History panel** (Settings): "Opens automatically" slides the side panel out on its own when a render starts; "Only when I open it" keeps it closed until you press the top-right button.
- Every turn carries a short balance note the agent reads before its first render: provider, credits or dollars left, known per-render prices. It picks a `--quality` the balance covers instead of submitting, getting a quota rejection, and retrying. Runs of `gen_image.py --help` are no longer shown as generations (they used to appear as a Failed tile: the "first generation always fails" bug). fal polling treats HTTP 202 as "still working", not failure.
- The credits pill follows the provider. ElevenLabs shows live credits. fal shows a live USD balance when the key is admin-scoped. Higgsfield has no balance API, so Settings has a balance field per provider: type what you have once and the pill counts it down using the pipeline's own logs (Higgsfield's per-render estimate, fal's unit price). The Approve button shows ElevenLabs credits, Higgsfield credits, or the fal price for that render.
- **Video: Seedance through PiAPI, or through the ElevenLabs Image & Video API.** A fourth key, PiAPI, is video-only and never takes part in the image priority. When no PiAPI key is stored, clips go through the ElevenLabs key instead (Settings > Video provider: Auto, PiAPI or ElevenLabs; the context note tells the agent which one is in effect and the tool picks it, the agent never passes `--provider`). On ElevenLabs the same tiers (Seedance 2.5 / 2.0 / Fast / Mini, plus Veo 3.1 and Veo 3.1 Fast which take no reference sheets and start at 720p) render for ElevenLabs credits; the sheets go inline as base64, nothing is uploaded to a public host. Kling is not on that API. Credits per clip are learned from `log.csv` after the first clip of a tier (the panel says "credits after the clip" until then, e.g. Veo 3.1 Fast 720p = 606 credits/s). ByteDance (Seedance) models are switched off by default on ElevenLabs accounts: the API answers 403 `model_access_denied` ("contact support to request access") and the clip card shows that reason with nothing charged. The pipeline's `tools/gen_video.py` sends the sealed video prompt plus the approved sheets in `video.refs.txt` as references (no start or end frame, no storyboard), waits for the clip and saves `scenes/scene-NN/video-vN.mp4`. PiAPI is pay as you go (top up in USD, no subscription): Seedance 2.5 bills per second of output, 480p $0.15, 720p $0.35, 1080p $0.80, so a 6 s clip is $0.90 / $2.10 / $4.80; a failed clip is refunded. PiAPI has no 2K or 4K tier: a job that asks for one renders at 1080p and the approval panel says so. Every clip stops on the same approval panel as images, with its own settings row (model, resolution, seconds 4 to 30, aspect 21:9 to 9:16, sound) and a live price; changes rewrite the command before it runs. The finished clip appears in the chat as an inline player with a full-screen control (the lightbox), and Approve / Disapprove work as for images. The Docs button next to the PiAPI key (key screen and Settings) walks through getting the key: sign in at piapi.ai/workspace, copy the key, top up on Billing, paste it here, with copyable blocks. References must be reachable by PiAPI: with a Creator plan or above they go through PiAPI's own temporary upload; on the free plan the tool falls back to a public 24 h temp host (litterbox.catbox.moe).

## What it does

- Models: the Claude models your Claude Code login can use (Auto, Opus, Fable, Sonnet, Haiku) with an Effort setting.
- Ask before generating: every `gen_image.py` / `gen_video.py` call pauses on an approval panel (Always allow / Stop [Esc] / Approve [Enter]). The request folds into the Generation row with the prompt underneath. Stop ends the run, like the stop button. Generate without asking runs them straight through.
- The Working row shows the agent's thinking live (click the row to fold it). Esc stops the run, same as the stop button.
- Clarifying questions from the agent appear as a numbered question panel (1-9 keys, Something else, Skip [Esc], Submit [Enter]). The chat dims while a request is open and the sidebar shows Needs reply / Needs approval.
- Every generation shows up under the answer as a 180px tile the moment it starts (Queued, then Processing, then the picture, or Failed with the reason such as not enough ElevenLabs credits). The side panel (Generate in Chat History) lists the same tiles with a Cancel button while they run. The Approve button on the approval panel shows the ElevenLabs credits the render will cost (from the pipeline's price table). Every rendered image or video pops up inline with Approve / Disapprove. Approve sends `approve <item> vN` to the pipeline; Disapprove sends your feedback. A file already saved as approved.png shows as Approved.
- Attach files with the plus button, paste, or drag and drop; they are copied to the uploads folder and handed to the agent by path.
- Every chat is a clean slate: the agent may only read this chat's own job folder plus the manuals, roles, libraries and tools. It never browses other jobs or briefs.
- Skills page has an Upload skill button: drop a Markdown skill (SKILL.md with frontmatter goes to `.claude/skills/<name>/`, a plain role file goes to `roles/`) and mention it by name in any chat.
- Content viewer lists the job's media; Projects, Skills, Library and Briefs pages read straight from the pipeline folder.
- The progress pill in the top bar (lime ring, `24/33`) counts the job's tasks from its `STATUS.md` table (files when there is no table yet). Click it for the task list: every item with Done / Working / Planned / Failed, its version, how many files it has and the pipeline's note. Click a finished task to see its picture, a planned one to open the job in the side panel; Open files opens the whole job.
- Ctrl+K (or the search icon) opens a search palette over chats, projects and briefs. Ctrl+Enter starts a new chat.
- Chats persist in `%USERPROFILE%\.supacomputa\chats` and resume the same Claude session. Each chat is auto-titled a few seconds after the first message.
- Each chat is one long-lived Claude session (streaming input). Background sheet agents keep working after your turn ends and still get the approval panel, so a plan that fans out to several agents no longer dies with "Stream closed". The session closes itself after 15 minutes idle and reopens on the next message.
- The pipeline session runs with strict MCP config, so none of your claude.ai connectors or user-level MCP servers are loaded into it.

## The browser panel and references first

- The side panel has three modes: **History**, **Browser**, **References** (plus **Blender** while Blender is connected, see below). It splits the screen like a VS Code editor split: the chat column, its top bar and the composer end where the panel begins, nothing overlaps. Drag the panel's left edge to make it wider or narrower (the width is remembered; the chat keeps at least 420 px, or 360 px in a narrow window).
- **Browser** is a real Chrome tab that fills the panel. It opens the moment you pick a site on the start screen (Pinterest, Google Images, Bing, Unsplash, Pexels) or type in the address bar; you never have to wait for the agent. If the tab cannot open (no Chrome or Edge installed), the start screen says why. Type words or a URL in the address bar, use the quick links (Pinterest, Google Images, Bing, Unsplash, Pexels), click, scroll and type in the page like any browser. Back / forward / reload up top. Ctrl+L jumps to the address bar. Sites sometimes show a captcha to a fresh tab; solve it in place.
- The tab always lays out at desktop width (at least 860 px) and the picture is scaled to fit the panel, so sites give their real layout even when the panel is narrow; drag the panel wider for bigger text. The tab uses one persistent Chrome profile (`%USERPROFILE%\.supacomputa\browser-profile`), so a login you do in the panel (Pinterest, Google) stays.
- Pinterest, signed out, covers the pins with a "Log in to see more" sheet that has no close button. The panel lifts that sheet and its scroll lock on every Pinterest page, for you and for the agent, so pins show and scroll without an account. Only `pinterest.com/login` is left alone, so you can still sign in there.
- **Pick** (top right of the browser, or hold Alt while clicking) saves the picture you click as a reference: it lands in a "your picks" set in References and in the job's `refs/scout/` folder. A pick made by mistake goes away with **Undo** on the toast or the x at the bottom right of its tile in References (the file is deleted too); **Remove set** in the set's header throws the whole set away. A click that hits no picture saves nothing and leaves no set behind. Once a set has been approved it stays as sent. It grabs the original where the page knows it (Bing and Google result links, srcset, Pinterest's larger sizes).
- Before the first render of any set (a sheet batch, a storyboard, a clip) the agent asks: "Should I create reference images first for the mug and the walnut table?" (Sir Leo's rule; the things named are the prompt's @tags, P-04 block 02). Click an answer and it goes at once, the card just closes (no Submit, no redraw); multi-choice questions keep Submit.
- On yes it runs `tools/scout_refs.py` once per thing in the same tab you see in Browser mode. Every scan is diversified: the tab visits Pinterest, then Pexels, then Google Images and takes a share from each (two from each for the default six), so a set never comes from one site; a site that gives fewer is topped up from the others. The status line names the site it is on. There is no "agent is browsing" indicator; the tab simply does it, and you can keep browsing while it works (the tab is shared). Stop the turn from the chat if you want it to stop.
- **Ctrl+W** (or Alt+W) closes the browser tab and the side panel with it, from the page, the address bar or anywhere in the app. In the Chrome app window Chrome itself owns Ctrl+W and closes the whole window, so Alt+W is the one to use there.
- Then **References** shows every open set: tap a picture to keep or drop it (a thin dark ring keeps the marks readable on any picture), right-click to view it large. **Approve** sends the kept files to the agent (attached to the render as `--ref`, in order); **Keep searching** asks for replacements for the dropped ones and never shows the same picture twice. The chat shows a short line ("References approved. mug: use 1, 2 ...") while the agent gets the full file list.
- The card in the conversation ("References for ...") has Watch / Review / Open to bring the panel back. A lime light runs around the border of whatever is working.
- The tab closes itself after 20 minutes without use, and when the chat is deleted. While the agent scouts, switching to References and back no longer snaps the panel back to the Browser tab.

## Connections and Blender clips

- **Connections** (sidebar > See more > Connections) connects the agent to programs on this machine. The first is **Blender**. Connect scans the usual install folders and PATH, picks the newest Blender that answers `--version`, and stores its path in `config.json`; "Point me at the file" takes a path when Blender lives somewhere unusual (only a file named `blender.exe` / `Blender` is ever launched). Disconnect forgets it. Nothing is installed or changed on your machine.
- **Why Blender:** Seedance cannot be told "cinebot, lightning fast, top shot, then frontal, then push into the label" and get it right; it can follow a clip that shows exactly that. With Blender connected, the agent writes a Blender Python script, Blender renders a low-poly **motion previz** (headless, no window) and the clip becomes the motion reference Seedance follows. What makes the motion read as a cinebot is written into `libraries/blender-previz.md` from Leo's own benchmark script: orbit-space camera states, quintic whip moves that stop dead, a slow creep during every hold, one keyframe per frame, motion blur on, a round studio; the worked example renders frame for frame like Leo's clip. The pipeline rule lives in that library and MAIN.md §5.3 step 0: on a shot with a choreographed camera move the agent asks once ("This shot has a complex camera move. Should I build it in Blender first, so Seedance has a motion reference to follow?"); a direct "Create a new blender project ..." builds at once. The agent writes the script itself (no subagent) to `jobs/<job>/scenes/scene-NN/previz-vN.py`.
- **In the chat** a Blender clip runs like a video (it is called Blender everywhere in the app; only the files on disk are named previz-vN): the script streams into the chat while it is written (a foldable code block; edits show the old lines in red and the new in green), the run stops on the **Approve Blender clip** panel (the `# Blender:` lines of the script, plus Resolution 720p to 4K, frames per second, seconds, engine Eevee or Workbench, aspect; no credits, the Approve button says "free"), the queued tile shows the latest rendered frame while Blender works, and the finished clip lands as a **Blender** card. The render runs in the foreground with a ten-minute tool budget; if the agent's tool call still times out, the app watches the job folder and turns the card into the clip itself. The card is the review: the agent says what the camera does and stops; it never pulls frames to judge the motion or renders a second version on its own, you ask for changes. Approve copies it to `previz-approved.mp4`. The clip is then the video blocking, prompted the way Leo prompts Seedance ("write a [x]-second prompt based on this video blocking, read the input video and write out second by second to match the camera moves, [x] fps, [x]:[x]"): the video director runs `tools/previz_frames.py`, which lays the clip out as labelled frames plus a contact sheet, reads them, and writes the ACTION block one line per second with the length, fps and aspect on the prompt's first line (the mp4 itself is not handed to `gen_video.py`). `tools/blender_previz.py` forces the settings, renders the frames and encodes them with ffmpeg when the machine has it, otherwise Blender writes the H.264 itself (nothing else to install), and logs a `scene-NN-previz` row with 0 credits.
- **Video cards** (Blender and Seedance clips) follow the Supercomputer look: a square tile with the clip letterboxed in it, a play glyph in the middle, three round icons that drop in from the top left on hover (add to the composer, download, full screen), the caption and a Blender / Video tag inside the tile, and under it only a pill, a copy button and the time. Approve / Disapprove are hover icons at the top right of the tile. A Blender clip card has a fourth icon on the left, Open in Blender: it shows the Blender tab and loads that card's scene, so a chat with several clips (the bottle, then the dog) can flip between them; the open Blender reloads in place.
- **The Blender tab** in the side panel appears only while Blender is connected. Open puts the real Blender inside the panel: the window loses its title bar and taskbar button, becomes part of the app window and fills the whole tab, so you work in the actual Blender (model, animate, scrub its timeline, every shortcut) with the real mouse and keyboard. It never shows anywhere else: it hides when you switch tabs, chats or close the panel, follows the app window when it moves, minimizes with it, and is never on the taskbar. It opens on the chat's newest previz scene looking through the cinebot camera in material preview, so the colours and the label look like the rendered clip (a headless-saved `.blend` has no viewport of its own). **Close** quits it. When a new previz finishes, the open Blender reloads it on its own. The window closes itself after 30 minutes idle and when the chat is deleted. On a Mac the panel shows viewport pictures taken by a small bridge inside Blender with its own transport bar (untested on a Mac). The window follows the panel through browser zoom, drags and layout changes; the page checks the window's size against the panel five times a second and, if it ever drifts, places it again and then restarts the helper that holds the window (`/api/blender/<chat>` shows `placed`, `host`, `castAlive`, `recasts`, `lastError`).
- **Acting.** Characters in a clip are directed with Leo's `libraries/Skills/ACTING SKILL.md` (954 lines, Seedance 2.5 first): the scene card gets ACTING lines (scene direction, situation, per character an objective, motive, tactic, tension, effort and eye task), the video prompt's PERFORMANCE block opens with a register line, carries one paragraph per character and positive-state Locks, every ACTION slice ends with a Subtext line, and the video director runs the library's checklist before it reports. Method names never reach a prompt.
- Rendering cost: about 0.5 s per 1080p Eevee frame on this laptop with the library's bottle scene (32 samples, motion blur on), so Leo's 200-frame shot is under 2 minutes; Workbench is a few seconds for a motion check.

## Sidebar and dropdowns

- Right-click a chat (or press its "..." button) for Rename, Pin/Unpin and Delete. Pinned chats sit in a Pinned section above the list. Rename edits in place (Enter saves, Esc cancels).
- Every dropdown in Settings is the app's own menu (no native select boxes).

## Shipping it as one EXE

`python packaging\build.py` writes `dist\Supacomputah-Setup.exe` (about 170 MB): a self-installing file that carries the app, its own Node and Python (embeddable), the Claude Code binary the Agent SDK ships, and a clean copy of the Leo Workflow kit. The other person double-clicks it; nothing has to be installed first (Chrome is used for the browser panel, Edge when Chrome is missing). It installs to `%LOCALAPPDATA%\Programs\Supacomputah`, puts a shortcut on the Desktop and in the Start menu, and starts `Supacomputah.exe`, a tray launcher that runs the server hidden, opens the app as its own window, restarts the server if it dies, and kills the whole tree on Quit. The pipeline lands in `Documents\Supacomputah\Leo Workflow`; updates refresh the manual, roles, tools and libraries once per version and never touch `jobs`, `briefs`, `scratch`, `refs-inbox` or `.env`.

Clean slate by construction: keys, chats, uploads and the browser profile live in the home folder and are never staged; `reference/`, `bin/`, `dist/`, the pipeline's `.git`, `jobs`, `scratch`, `refs-inbox`, `browser-profile` and `.claude/settings.local.json` are skipped; the manual's example paths are rewritten to the recipient's layout; and the build stops if any forbidden string (names, emails, local paths, key shapes) is found in a shipped text file. The recipient logs in to Claude from the app (it opens a terminal on the bundled binary) and pastes their own provider keys in Settings.

Test switches: `Supacomputah-Setup.exe --dir=<folder> --no-shortcuts --no-launch --silent`; `Supacomputah.exe --no-window`; the launcher honours `SUPACOMPUTA_PORT`, `SUPACOMPUTA_HOME` and `SUPACOMPUTA_PIPELINE`. Toolchain: the C# compiler in every Windows (.NET Framework 4.x) and Python's zipfile. No NSIS, no Electron.

## Shipping it for a Mac

`python packaginguild-mac.py` writes `dist\Supacomputah-Mac.zip` (about 330 MB), built entirely on Windows. It unzips to one `Supacomputah` folder: `Supacomputah.app` (a bundle whose executable is a shell script), the same script as `Start Supacomputah.command`, `Stop Supacomputah.command`, `Log in to Claude.command`, `READ ME FIRST.txt`, `app/` with the darwin-arm64 and darwin-x64 Claude binaries from the SDK's own npm packages (checksums verified against the SDK manifest, the Windows binary dropped), `runtime/darwin-<arch>/` with Node (official tarball, checksum verified) and a standard-library-only Python from python-build-standalone for both chips, and the same clean `pipeline-template/`. The launcher picks the chip with `uname -m`, clears the download stamp (`com.apple.quarantine`) from the folder on first run, seeds or updates `~/Documents/Supacomputah/Leo Workflow` with the same keep-list as the Windows launcher, starts the server in the background (log in `~/Library/Logs/Supacomputah/server.log`) and opens Chrome as an app window (default browser when Chrome is missing). No `.dmg` and no signature: a script-based app cannot be code-signed, so the README's first step is one Terminal line (`xattr -cr` on the folder) and the alternative is Privacy & Security > Open Anyway. The zip is written with Unix modes and symlinks, which Archive Utility restores. The server side needs no Mac-specific code beyond `agent.js` looking for the bundled runtime under `runtime/darwin-<arch>/…/bin` and `auth.js` opening Terminal through `osascript` for the login. Downloads are cached in `dist\cache-mac`.

## Safety notes

- The server binds to 127.0.0.1 only.
- `/api/file` serves only media inside the pipeline root and the uploads folder.
- No key ever appears in a response body, a log line, a chat transcript, or the repository. `config.json` is git-ignored. PiAPI keys are verified with a free `/account/info` call. Provider checks send a `Supacomputah/1.0` user agent because Higgsfield's Cloudflare rejects anonymous clients.
